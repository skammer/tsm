# tsm

[English](README.md)

Менеджер сохранённых состояний tmux на Rust. macOS / Linux, tmux 3.3+.

## Запуск

```sh
cargo build --release
./target/release/tsm
```

Установка в `~/.cargo/bin`:

```sh
cargo install --path . --locked
```

## CLI

```sh
tsm save
tsm save window -n "Marginalia"
tsm save session -n "Personal projects"
tsm save session work            # сессия по имени или уникальному префиксу
tsm save window 2                # окно по индексу
tsm save 3                       # то же: не-scope значение — цель окна
tsm save window logs             # окно по имени или уникальному префиксу
tsm save window work:2           # окно в другой сессии
tsm save all -n "Everything"
tsm peek
tsm peek session -n "Personal projects"
tsm peek work:logs
tsm peek all
tsm save window -n "Marginalia" --dry-run
tsm list
tsm list -f "Pers"
tsm inspect "Personal projects"
tsm inspect "Personal projects" logs   # только одно окно снапшота
tsm restore "Marginalia"
tsm restore
tsm delete "Marginalia"
tsm rm "Personal projects"
tsm merge id-1 id-2 -n "Merged sessions"
tsm merge id-3 --into id-4 -n "Updated id-4"
tsm list --color always
```

`save` и `peek` по умолчанию сохраняют текущее окно или сессию, либо явную цель: окно — по индексу, имени или уникальному префиксу имени (можно `session:window`), сессию — по имени или уникальному префиксу. Первый позиционный аргумент, не являющийся scope (`window`/`session`/`all`), трактуется как цель окна, поэтому `tsm save 3` работает. Цели по имени (`session:window`, имя сессии) требуют только доступный tmux-сервер, а не `TMUX_PANE`. Цель несовместима со scope `all`.

`peek [window|session|all] [TARGET] [-n NAME]` показывает текущее состояние в формате `inspect`, используя тот же сбор данных, что и `save`. `save --dry-run` делает то же самое. Хранилище не читается и не создаётся, файлы не записываются. UUID в выводе временный; последующий `save` создаст новый. Захват текущего окна/сессии требует запуска внутри tmux; именованные цели и all — только доступный tmux-сервер.

`inspect` принимает необязательный второй позиционный аргумент — показать одно окно снапшота по индексу, имени или префиксу имени.

`inspect`, `restore`, `delete` и `merge` принимают точное имя, полный UUID или любой уникальный префикс UUID, с дефисами или без. `list` показывает минимум 8 символов и удлиняет ID при коллизии. Неоднозначный ID/имя вызывает ошибку со списком UUID. Каждое сохранение создаёт новый snapshot; одинаковые имена разрешены.

Цвета включены автоматически в терминале, отключены при перенаправлении вывода, непустом `NO_COLOR` или `TERM=dumb`. Глобальный `--color auto|always|never` управляет цветами вывода команд.

`delete` (алиас `rm`) удаляет выбранную запись без дополнительного подтверждения; запущенные tmux-сессии не затрагиваются.

`merge` без `--into` требует минимум две записи и создаёт новый UUID. Без `-n` имена склеиваются через `", "`. С `--into` достаточно одной исходной записи: получатель обновляется атомарно, сохраняя UUID, дату создания и имя; `-n` переименовывает его. Исходные записи остаются в хранилище. Повтор одного UUID, включая получателя среди источников, вызывает ошибку.

Одноимённые tmux-сессии объединяются по окнам, разные сессии сохраняются отдельно. Все окна и panes сохраняются, даже при совпадении содержимого. При конфликте индекса добавляемое окно получает минимальный свободный индекс; остальные индексы сохраняются. Layout и команды panes не меняются. Активное окно берётся из первой записи для данной сессии (получатель `--into` идёт первым). Результат имеет тип `session`, если сессия одна, иначе `all`.

Фильтр — префикс имени без учёта регистра (включая кириллицу), либо префикс UUID. `Pers` найдёт `Personal projects`, но не `My Personal projects`. Звёздочка не нужна.

`save` / `save window` и `save session` без цели запускаются внутри tmux. Источник определяется по `TMUX_PANE`, а не по последней активной сессии другого клиента. `save all` сохраняет все сессии **текущего tmux-сервера**.

`restore` без аргумента восстанавливает самое свежее сохранение:

- Window внутри tmux → новое окно в текущей сессии.
- Window вне tmux → новая отдельная сессия с именем snapshot.
- Session → новая сессия с именем snapshot.
- All → новые сессии с исходными именами tmux-сессий.
- При конфликте имён добавляется `-restored-N`.
- Существующие окна/сессии не заменяются. Автоматического attach/switch нет.
- Ошибка построения → удаляются только созданные этим restore объекты. Побочные эффекты уже запущенных программ отменить невозможно.

## TUI

Просто `tsm`:

| Клавиша | Действие |
| --- | --- |
| ↑/↓, j/k | Выбор snapshot; в инспекторе — прокрутка |
| Tab / Enter | Переключение списка и инспектора |
| PgUp / PgDn, Home | Прокрутка / начало инспектора |
| / | Ввод префиксного фильтра; Enter/Esc завершает ввод |
| w / s / a | Сохранить window / session / all; ввести имя или Enter для имени по умолчанию |
| r | Восстановить выбранный snapshot |
| d / Delete | Удалить выбранный snapshot: y подтверждает, n/Esc отменяет |
| i | Показать/скрыть подробности: UUID, Layout, активные окна/panes, zoom, исходную команду |
| g | Перечитать сохранения с диска |
| q / Ctrl-C | Выход |

## Что сохраняется

Имена сессий/окон, индексы окон, layout, активные окна/panes, zoom, заголовки panes, cwd, текущие программы и аргументы. Аргументы читаются отдельно от окружения процесса через `KERN_PROCARGS2` на macOS и `/proc/PID/cmdline` на Linux. Shell quoting сохраняет аргументы с пробелами и спецсимволами.

Текущий вызов `tsm` исключается из команд snapshot по PID и дереву процессов — в том числе при запуске через shell-обёртку или переименованный бинарник. У этой pane сохраняются layout, заголовок и cwd, но очищаются все поля команд (`command`, `command_line`, `argv`, `start_command`). При restore открывается обычный shell. То же правило действует для `peek`, `save --dry-run` и сохранения из TUI.

Восстановление **перезапускает** программы. Память процесса, история терминала, несохранённые буферы редактора, shell history, окружение, пайплайны и фоновые jobs не сохраняются. Для произвольного pipeline определяется один foreground process group leader; исходная shell-команда целиком не гарантируется. Интерактивные shells и сам `tsm` заменяются новым shell из `default-shell`; shell-скрипты с аргументами запускаются заново.

Отсутствующий cwd вызывает ошибку до создания объектов. Быстро завершившиеся команды сохраняют pane через `remain-on-exit`. Программы могут позже сами изменить заголовки panes. Геометрия может масштабироваться при другом размере терминала. Связанные окна разных сессий восстанавливаются отдельными копиями. Опции tmux, кроме нужных для восстановления, не архивируются.

## Хранилище

Отдельный JSON на UUID, атомарная запись, права файла `0600`. Новые сохранения не перезаписывают существующие; `merge --into` атомарно заменяет только получателя:

- macOS: `~/Library/Application Support/dev.tsm.tsm/snapshots/`
- Linux: `$XDG_DATA_HOME/tsm/snapshots/`, обычно `~/.local/share/tsm/snapshots/`
- `TSM_DATA_DIR` задаёт каталог snapshots напрямую.
- `TSM_TMUX_SOCKET` задаёт путь сокета tmux для отдельного сервера.

Повреждённые и неподдерживаемые snapshots пропускаются с предупреждением. Команды могут содержать секреты в аргументах — JSON содержит эти аргументы, но не весь environment.

## Проверка

```sh
cargo fmt --check
cargo test
cargo clippy --all-targets -- -D warnings
cargo test --test tmux_roundtrip -- --ignored
```

Обычные тесты проверяют также CLI-цвета, удаление, merge и сохранность файлов при ошибках. Последняя команда запускает тесты на отдельных временных серверах tmux: layout, argv, все scopes, поиск, rollback, восстановление merge и взаимодействие с TUI. Требует разрешения запускать tmux и читать процессы. Рабочий tmux-сервер не используется.

## Структура

`model` — формат snapshot и валидация; `store` — файловое хранилище; `query` — поиск и short ID; `tmux/client` — вызовы tmux; `capture` / `restore` — сохранение/восстановление; `process` / `command` — argv и запуск; `cli` / `tui` — интерфейсы.

Ratatui закреплён на 0.30.2: для точной прокрутки используется feature `unstable-rendered-line-info`. Семантика создания panes сверена с [исходниками tmux](https://github.com/tmux/tmux/blob/master/cmd-split-window.c).
